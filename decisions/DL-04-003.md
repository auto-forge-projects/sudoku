# DL-04-003: Doğrulama+render = tam doğrulama + hedefli DOM class güncellemesi

- Tarih: 2026-07-25
- Faz: 4 — Çözüm Analizi
- Mod: AUTOPILOT
- Karar: Her girdide tahtanın tamamı doğrulanır (27 grup / ~243 karşılaştırma, <1ms) ve ihlalli hücre kümesi hesaplanır; DOM'daki 81 hücre elemanı ÖMÜR BOYU sabit kalır, yalnız değişen hücrelerin CSS class'ları güncellenir (`innerHTML` ile yeniden kurma yok). Olay dinleme delegasyonla grid kökünde yapılır.
- Değerlendirilen alternatifler: (A) tam doğrulama + tam `innerHTML` re-render; (B) artımlı doğrulama — yalnız değişen hücrenin 20 peer'i.
- Gerekçe: A'yı eleyen somut sebep NFR-4 — re-render odağı kaybettirir, ok tuşlarıyla gezinme ve klavye girişi kırılır. B'yi eleyen sebep hata yüzeyi: peer invalidasyonu (özellikle silme sonrası vurgu kalıntısı) sessiz hata üretir; 9x9'da tam tarama zaten bedava olduğu için karmaşıklığa değmez. Gerçek darboğaz DOM yazımıdır, o da hedefli class diff'iyle minimize edilir → NFR-1 rahat karşılanır.
- Riskler: Class diff'i eksik uygularsak eski vurgu kalır → render her zaman TÜM 81 hücrenin beklenen class durumunu uygular (diff yalnız yazımı azaltır, kararı değil).
- Geri alınabilirlik: Yüksek — doğrulama saf fonksiyon; render stratejisi tek dosyada, isterse artımlıya çevrilebilir.
